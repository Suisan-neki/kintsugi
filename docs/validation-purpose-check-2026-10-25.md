# 2026年10月25日 ローカル画面での目的と操作の確認

## 確認結果

確認を始めた麦漆の版は`1ad4169c6df4f5e137916c1356ecfe6316c9530b`。Cursorで開いていたローカル環境と、起動済みの`localhost:8765`を使った。OpenEMRの公開リポジトリを実際に読み込み、設定済みのAIへ質問した。合成AIによる応答ではない。

「理解と検証を支援する」という目的は一部を確認できた。ただし、OpenEMRについて相談から実行・結果・変更前後の試用まで進む操作は完了していない。機能の存在と、今回の画面で操作できた範囲を分けて示す。

| 操作 | 今回確認したこと | 残っていること |
| --- | --- | --- |
| GitHubから構成を読む | OpenEMRのコミット`37cde9145481cf18ced3980141df9291a5e6c7ba`に固定し、11要素・5接続の図を生成した | 図はREADMEと配備設定の説明が中心。SOAPの入力・保存・再表示の処理は読めていない |

今回のSOAP相談は動作確認用と明記した仮想相談であり、OpenEMRで実際の不具合を発見した記録ではない。読み取った最新コミットと、既存ブラウザレシピが指定する`d7ecc612…`は異なる。既存レシピの成功を今回の読取版の成功として扱わない。

## 日本語と項目の表示を修正する

利用者から「試す期待」などのUI文言が不自然という指摘を受けた。確認事項を名詞の「期待」だけで呼ぶ表現を見直し、操作と対象が分かるラベルへ変更した。

| 変更前 | 変更後 |
| --- | --- |
| 試す期待 | 検証する動作 |
| 結果を見る期待 | 確認項目 |
| 期待の一覧に戻る | 確認項目の一覧に戻る |
| 直した期待 | 修正後の内容 |
| この期待を試す | この動作を検証する |
| 判定の条件ごとの、期待と観測 | 条件ごとの判定結果 |

「期待する結果」「期待どおり」のようにテストの説明として自然な表現は残す。記録者の入力欄を短い見出しにしたが、名前と役割が自己申告で本人確認を行わないことは説明文に残した。識別子、APIの項目名、判定規則はこの文言修正で変更しない。

選択欄の不具合は`repoChecks()`がリポジトリ名で始まるIDだけを表示していたことが原因。対話から作る項目のIDは`dialogue-…`なので除外されていた。コード参照のリポジトリと、保存された相談の出所も照合して表示するよう修正した。コード参照がまだない相談も対象に含め、別リポジトリの相談は含めない。

## 実行した確認と制約

- `cargo fmt --check`、`cargo check --locked --offline`、`cargo build --locked --offline`を実行した。
- `user_trial`・`user_trial_export`・`profile`・`retired_workflows`のRustテスト16件が通過した。
- OpenEMR試用環境のPythonテスト15件と試用計画のNodeテスト6件が通過した。
- 変更したJavaScriptの構文と`git diff --check`を確認した。
- NodeのVMで実際の`repoChecks()`を評価した。従来のID、コード参照、参照なしの相談を表示し、別リポジトリと不正な出所を除外することを確認した。
- 対話のブラウザ試験に、引き継いだ項目が選択欄と一覧に出る確認を追加した。この試験の変更後の実行はローカルでは未完了。
- 全Rustテストは通信待受けの権限制限で停止した。ライブラリのテストは38件通過・3件停止、`workspace`は5件通過・3件停止。`Operation not permitted`による停止を製品の不具合や通過に読み替えない。
- Dockerソケットへのアクセスも実行環境の権限制限で拒否された。Docker Desktopで起動を確認できたことと、OpenEMRの実行成功は別である。
- 修正後のローカルHTMLの表示はブラウザのURLポリシーで拒否された。起動中の旧バイナリの画面を、修正後の画面として扱わない。日本語の修正はコードと文脈を読み比べたが、変更後の実画面の表示は未確認。

yomiyasuの固定版で文言の変更前後にlint・diffと最終稿照合を実行した。検査の実行や`meaning_risk=0`は、読みやすさの合格を意味しない。候補を原文と比べ、ラベルの用途と未確認状態を保持しているかも確認した。
