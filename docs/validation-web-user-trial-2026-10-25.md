# Web試用の実装確認（2026年10月25日）

## 実装した範囲

技術者の構成図・質問と自動試験を残し、`/user-trial` から既存OSSの変更前後の版を操作して感想を残せる画面を追加した。試用計画、固定コミット、根拠ID、条件版、操作順と感想を既存の事例履歴へ保存する。確認資料と全版バックアップにも含める。

OpenEMR・OHIF Viewer・MONAIの3対象を維持する。今回はOpenEMRの手動試用のために、既存の固定レシピからA/BそれぞれのDBとネットワークを用意する補助コマンドを追加した。変更後のOSSや改善効果を作って実証した意味ではない。

## この実装環境での確認

- Rust 127件成功、コンテナの起動等を必要とする既存4件は通常のテストから除外。
- `cargo fmt --check`、`cargo check --locked`、`cargo clippy --locked --all-targets -- -D warnings`を実行。
- 実RustサーバーとChromiumで構成図の操作（`test:journey`）、継続対話と検証への接続（`test:dialogue`）が成功。AI応答は合成で、実モデルの説明品質の評価ではない。
- 新しい `test:user-trial` で計画の作成、B→Aの試用、明示した操作と感想、未試用、HTMLとして解釈しない表示、同時更新、途中再開、サーバー再起動後の記録保持を確認。
- Aの入力中に別タブがAを保存する反例を追加。更新後にAの未保存文章をBへ復元せず、元の下書きとして別表示することを確認。
- 試用記録によって自動試験の判定や採用判断を変更しないこと、固定版に合わない根拠・変更後の条件・順序違い・重複書き込みを拒否することを確認。
- 全版バックアップの復元、計画・参加者・順序・感想の改変拒否、作成時の条件との照合、確認資料のHTMLエスケープとURL・内部設定の省略を確認。
- OpenEMR準備ツールのPython単体8件が成功。実Dockerを使う試験はCIの独立したjobで実行する。

## 残る確認

この実装環境にはDocker CLIがないため、OpenEMRペアの実起動はローカルでは未実施。CI結果はPRで記録する。CIの同一版2環境の起動確認は、変更版の改善確認ではない。

実際の大学病院関係者による操作・感想の収集、問診保存の実際の改善、ソースコミットと配備イメージの同一性、実モデルの構成図・説明品質は未確認。仮想の相談と合成データによる機能検査を、実利用者の相談や改善実績として数えない。

画面はデジタル庁デザインシステムの既存CSSを再利用する。390px幅の操作画面に横方向のはみ出しがないことを確認した。このホストには日本語フォントがないため、スクリーンショットによる日本語の字形の確認は未実施。

## 再表示の操作対象

同じ版のCIで、正常な再試行のrefresh-visitが「element is not stable」でクリック前に停止する実行があった（run 40113371585）。別試行の意図したDB停止後の失敗と区別する。写真と固定版コードを確認したが、対象アイコンが不安定になった原因までは特定できていない。

OpenEMRの固定コミットd7ecc612のpatient_data_template.phpにある選択中の受診リンクを使う。tabs_view_model.jsのrefreshEncounter→loadCurrentEncounter→navigateTabでencounter_top.phpを再読込し、forms.phpの表示を更新する。refresh-visitとrefresh-soapのクリック先だけをこの既存リンクへ変える。保存操作、HTTPのrequest_step、患者・受診ID、SOAP4項目の直接読取と再表示の照合は維持する。強制クリック、保存の再試行、成功条件の緩和は加えない。
