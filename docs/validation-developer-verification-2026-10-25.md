# 開発者向けの方針変更と操作の確認（2026年10月25日）

対象と目的は[現在の方針](developer-verification.md)、作業は[#184](https://github.com/Suisan-neki/mugiurushi/issues/184)。本記録は今回の画面・対話・互換性の確認であり、検証負担の軽減や医療機関での有効性を実証したものではない。

## 実行した確認

- Rust 1.99.0で`cargo fmt --check`・`cargo check --locked`・`cargo test --locked`・`cargo clippy --locked --all-targets -- -D warnings`・`cargo build --locked`。
- `npm run lint`・`npm run typecheck`・`npm run test:api`・`npm run test:reader-native`。
- `python3 tools/check-yomiyasu.py`で固定版の規則と上流の検査器を確認。
- `EEL_DIALOGUE_API_ONLY=1 npm run test:dialogue`とNativeの同じAPI試験。合成Difyと合成Nativeモデルの双方へ、開発者の技術的な検証という目的と説明の詳しさを渡すことを確認。
- 実RustサーバーとChrome Headless Shell 156.0.8078.47で`test:journey`・`test:dialogue`・`test:user-trial`。保存済みの固定版と合成AIを使う。実モデルの説明品質の評価とは区別する。

## 操作で確認したこと

入口では立場選択を求めず、公開リポジトリの入力と記録済みの検証項目を表示する。構成図を作らず検証画面を開ける。旧画面の非技術者の表示設定を残した状態でも技術情報を既定にする。

概要と技術情報を切り替えても、記録者の名前・役割と条件・根拠・判定を変更しない。旧画面が立場から自動作成した匿名の記録者は新しい既定へ移し、人が記入した名前と役割は保持する。概要表示で新たに作った検証課題も開発者の記録として保存する。

記録済みの項目から、AI接続が利用できない場合でも設定へ直接戻る。結果から対象のコミットと図を作ったコミットが異なる場合も、それぞれの参照を保持する。観測が欠けた結果は判定不能として表示し、結果・比較の画面へ戻れる。

図の根拠・選択箇所・草稿・会話・図の版への復帰を確認する。1440px・390px・320pxと文字サイズ200%で操作し、横にはみ出さないことを確認する。入口・構成図・検証履歴・結果の画像を目視した。

既存のWeb試用の直接の入口と保存機能を試験し、主導線から外した後も試用記録を扱えることを確認する。実利用者の試用は行っていない。

## 実行環境と未確認事項

今回のローカル環境にDockerはない。SOAP用ブラウザレシピの対象版への切り替えと観測設定の表示までは確認したが、実行前確認への操作はDocker不足の表示で無効になる。対象OSSを起動した試験や正常時・DB停止・復旧の新しい実測は実施していない。DockerがあるCIでの合成ブラウザ接続試験はPRのチェック欄を参照する。

固定指定のChromium 151のダウンロードがローカル環境では完了せず、UI操作の確認には別途取得したHeadless Shell 156を使った。医療OSSの固定レシピで指定するChromiumの版は変更していない。CIでは既存の固定版を使う。

実Difyの公開済みChatflowの編集や実API接続、実モデルの回答品質、要件・ガイドライン全体への適合、任意アプリの環境準備と計測、VMスナップショットからの復元、検証にかかる負担の比較評価は今回確認していない。
