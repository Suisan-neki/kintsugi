# mugiurushi(麦漆)

**医療システムの開発者がソフトウェアの動作を理解し、検証するための実行観測基盤です。**

医療システムが意図したとおりに動くことを、どのように確かめればよいか。mugiurushiは開発者が抱く不安やシステムの構成をもとに検証する内容を整理し、実際の動作を観測して、確認できたことと残る課題を示すことを目指しています。

「麦漆」は金継ぎで接着に使う材料です。検証の結果を改善・改修へ引き継ぎ、開発者とユーザーを「しっかりくっつける」という思いを名前に込めています。

医療システムを提供するには、機能を作るだけでなく、医療情報の安全管理や個人情報の保護、診療記録の保存、障害時の対応、導入先の接続・運用条件などを確認する必要があります。対象に応じて法令やガイドラインを確認し、医療機関との役割分担も考えなければなりません。システムによっては、医療機器に関する規制への対応も必要です。

医療分野に新たに参入する開発者にとって、これらの要件を把握し、何をどこまで、どのように確かめるか判断することは負担になります。生成AIなどによってソフトウェアを作る方法が広がる中でも、作ったものを理解し、運用に向けて検証する作業は欠かせません。mugiurushiは必要な確認と検証を支援することで、医療システム開発への参入障壁を下げたいと考えています。

例えば、小規模病院へ納品する電子カルテを開発したとします。画面が動いていても、データベースの設計は要件に合っているのか、診療データは意図した場所に保存されるのか、個人情報を守る対策は十分なのか、不安が残ります。

運用を見据えた開発に「ここまでやれば絶対安全」という線引きはありません。変化し続けるリスクに向き合いながら、開発者が何を確認し、どのような結果を得たのかを、ある程度客観的に示せるようにしたいと考えています。

## プロダクトの概要

![4ページ目：プロダクトの概要](docs/images/presentation/slide-04.png)

![7ページ目：システムの仕組み](docs/images/presentation/slide-07.png)

mugiurushiはAIエージェントとRustによる実行・観測基盤を組み合わせ、医療ソフトウェアの動作と要件の確認を支援することを目指しています。

例えば「診療データが正しく保存されているか確信が持てない」という場合、開発者が次のように検証を進められることを目指しています。

1. AIが開発者の不安やシステムの構成・コードをもとに、検証すべき内容を整理します。開発者は提案された検証条件を確認し、期待する結果と観測方法を設定します。
2. 実行・観測基盤が対象システムを試験環境で動かし、診療記録の保存に関わる処理やデータの動きを観測します。応答、画面表示、ログ、保存状態などを確認します。
3. 開発者は観測結果と期待する動作を照らし合わせ、確認できたことと残る課題を整理します。その結果をもとに、必要な修正と再検証につなげます。

実行の条件や対象の版も記録することで、改修後の結果と比較できるようにします。医療情報を扱うための要件と観測結果を照らし合わせ、必要な確認事項の過不足を整理するAIエージェントも構想しています。

現在は構成図の生成、試験条件の設定、対象の実行と観測、結果の記録・比較を実装しています。構成図を使わず、検証内容を直接設定することもできます。医療分野の要件と観測結果を照らし合わせる機能は今後の開発対象です。AIの説明と実際に得られた観測は区別し、証拠が足りない場合は判定不能として扱います。

## mugiurushiが支援したいこと

![8ページ目：目指すべき未来](docs/images/presentation/slide-08.png)

mugiurushiの主な利用者は、医療システムを開発・提供する人です。開発者が確認の根拠を持ち、検証できた内容や残るリスクを医療機関に説明できる状態を目指しています。

開発者と医療機関がリスクや運用上の懸念を共有し、それぞれの役割と責任の分担を話し合えるようにしたいと考えています。さらに、医療従事者が患者の医療システムに対する不安に向き合い、説明できることも目指しています。

開発者、医療機関・医療従事者、患者が納得しながら、システムの開発から運用までを進められることが目標です。
